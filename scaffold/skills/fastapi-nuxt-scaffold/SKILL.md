# FastAPI + Nuxt Scaffold

## Overview

Scaffolds a two-tier app: an async FastAPI backend exposing **two separate API surfaces**
as sub-apps (each with its own CORS posture, auth dependency, and OpenAPI schema), and a
Nuxt 4 + Vuetify 4 frontend whose entire API client (TS types, validation schemas, typed
SDK) is **generated** from one of those surfaces' OpenAPI schema — never hand-written.

Core principle: the OpenAPI schema is the contract. Nothing about the wire format is
duplicated by hand between backend and frontend.

## When to use

- Starting a brand-new app that wants: a browser-facing admin/console API, a separate
  server-to-server integrations API, and a Nuxt+Vuetify frontend consuming the former.
- Replicating this exact architecture pattern into a fresh project — not extending an
  existing app that already has it.

Not for: adding a single new endpoint or page to an existing app (just follow the existing
app's own conventions), or apps that only need one API surface with no external
integrations.

## Required inputs — ask before creating anything

This skill needs exactly two things: **`appName`** (kebab-case, used as the directory name,
project name, and title strings) and **`targetDir`** (absolute path to create the project in).

**If either is missing from the request, stop and ask the user before writing any file or
running any command.** Never invent a project name, never guess a directory, never scaffold
into the current directory "as a reasonable default" — an unconfirmed `targetDir` is exactly
the kind of mistake that's expensive to undo (wrong location, wrong repo).

## Package versions: always via the package manager, never hand-pinned

`uv add` / `uv add --dev` and `npm install` / `npm install -D` are the ONLY way dependencies
enter `pyproject.toml` / `package.json`. Do not hand-write a version number into either file.
Hand-pinned versions go stale the moment they're written and drift from whatever's actually
installed — this is not hypothetical: an earlier version of this skill shipped a fully
pre-written `pyproject.toml`, and by the time it was tested months later its own hand-picked
mypy/pydantic-settings versions no longer agreed with each other, failing the skill's own
required `mypy` gate. Reference files below only ever hold **tool config** (ruff/mypy/pytest
sections, npm scripts) — never a dependency list.

## Architecture

```
<targetDir>/
  .gitignore                    # from references/gitignore.root
  CLAUDE.md                     # from references/CLAUDE.root.md
  api/
    .gitignore                  # from references/gitignore.api
    CLAUDE.md                   # from references/CLAUDE.api.md
    main.py                     # from references/main.py (replaces the `uv init` stub)
    environment.py              # from references/environment.py
    pyproject.toml               # generated by `uv init` + `uv add`, then
                                  # references/pyproject-tool-config.toml appended
    .env.example                  # from references/env.example
    .env                          # created in the Steps below; gitignored, never committed
    alembic.ini                   # generated by `alembic init -t async migrations`
    lib/
      __init__.py
      database.py                # from references/database.py
      enums.py                   # empty; StrEnums go here
      utils.py                   # from references/lib_utils.py
    models/
      __init__.py                 # imports base + enum_tables (and every future model module)
      base.py                    # from references/models_base.py
      enum_tables.py             # from references/enum_tables.py
    routers/
      __init__.py
      rest/__init__.py            # empty APIRouter(), no auth yet (see below)
      api/
        __init__.py               # APIRouter(dependencies=[Depends(verify_api_key)])
        deps.py                   # from references/routers_api_deps.py
    schemas/
      __init__.py
      rest.py                     # empty
      api.py                      # empty
    services/__init__.py
    migrations/
      env.py                      # from references/migrations_env.py -- OVERWRITES the generated one
      ...                         # everything else generated by `alembic init -t async migrations`
    tests/
      test_health.py              # from references/test_health.py
  gui/
    # scaffolded by `nuxi init` FIRST (into this still-empty directory), then these
    # copied on top, each REPLACING the nuxi-generated file of the same name/path:
    CLAUDE.md                     # from references/CLAUDE.gui.md
    nuxt.config.ts                # from references/nuxt.config.ts
    openapi-ts.config.ts          # from references/openapi-ts.config.ts
    uno.config.ts                 # from references/uno.config.ts
    eslint.config.mjs             # nuxi-generated, edited per references/eslint-generated-ignore.md
    .gitignore                    # nuxi-generated, appended per references/gitignore.gui-additions
    package.json                  # nuxi-generated + npm install'd deps; "scripts" merged from
                                   # references/package-scripts.json; "name" renamed to appName
    app/
      app.vue                      # from references/app.vue
      plugins/
        vuetify.ts                  # from references/vuetify-plugin.ts
      generated/rest/                # populated by `npm run openapi`; only openapi.snapshot.json is committed
```

Two surfaces, mounted as **separate FastAPI sub-apps** in `main.py` (see
`references/main.py` for the full pattern):

| Surface | Consumer | CORS | Auth |
|---|---|---|---|
| `/rest` | Browser (the `gui/` app) | locked to the frontend origin(s) | none wired yet — deliberately deferred; add session/OIDC/etc. when the app needs it |
| `/api` | Server-to-server integrations | open (`*`, no credentials) | static API-key header check (`references/routers_api_deps.py`) |

The frontend (`gui/openapi-ts.config.ts`) generates its client **only from `/rest`** — an
integrating system generates its own client from `/api`'s schema separately. Never let the
GUI call `/api` or vice versa; if a route is genuinely needed on both, implement it once per
surface and share the underlying logic through a `services/` function.

## Steps

1. **Confirm inputs.** Get `appName` and `targetDir` (ask if not given — see above).

2. **Backend init.** `mkdir -p <targetDir>/api && cd <targetDir>/api`, then:
   ```bash
   uv init --app --name <appName> --vcs none --no-readme .
   uv add fastapi "uvicorn[standard]" "sqlalchemy[asyncio]" asyncpg alembic pydantic pydantic-settings
   uv add --dev ruff mypy pytest pytest-asyncio httpx
   ```
   This creates `pyproject.toml` (with real, current dependency versions) and a stub
   `main.py`/`.python-version`. Append the **entire contents** of
   `references/pyproject-tool-config.toml` to the generated `pyproject.toml` (tool config
   only — never touch the `[project]`/dependency sections `uv` just wrote).

3. **Copy backend reference files** over the `uv init` stub, replacing `__APP_NAME__` with
   the real `appName` wherever it appears (`main.py`, `.env.example`; grep afterward to
   confirm none survive): `main.py`, `environment.py`, `.env.example`, `lib/database.py`,
   `models/base.py`, `models/enum_tables.py`, `routers/api/deps.py`, `tests/test_health.py`,
   `CLAUDE.md` (root, into `<targetDir>/`), `api/CLAUDE.md`. Also create:
   - `lib/__init__.py`, `lib/enums.py` (empty)
   - `models/__init__.py` — imports every model module so Alembic autogenerate sees it (add
     to this import line as real model modules are added later):
     ```python
     from models import base, enum_tables  # noqa: F401
     ```
   - `schemas/__init__.py`, `schemas/rest.py`, `schemas/api.py` (empty)
   - `services/__init__.py` (empty)
   - `routers/__init__.py`, and the two surface packages:
     ```python
     # routers/rest/__init__.py
     from fastapi import APIRouter

     router = APIRouter()
     ```
     ```python
     # routers/api/__init__.py
     from fastapi import APIRouter, Depends

     from routers.api.deps import verify_api_key

     router = APIRouter(dependencies=[Depends(verify_api_key)])
     ```
   - `.gitignore` at `<targetDir>/` (from `references/gitignore.root`) and `<targetDir>/api/`
     (from `references/gitignore.api`).

4. **Backend env + migrations.**
   ```bash
   cp .env.example .env   # DB_USER, DB_PASSWORD, DB_NAME have no default -- the app fails to import without them,
                           # even for routes that don't touch the DB. create_async_engine connects
                           # lazily, so a syntactically valid but not-yet-live Postgres URL is
                           # enough to boot the app and pass test_health; only /health/db and real
                           # queries need a reachable database.
   uv run alembic init -t async migrations
   ```
   Then overwrite the generated `migrations/env.py` with `references/migrations_env.py`
   (points Alembic at the app's own `lib.database.engine` and `models.base.Base.metadata`
   instead of a URL hardcoded in `alembic.ini`).

5. **Frontend init.** `mkdir -p <targetDir>/gui && cd <targetDir>/gui` — the directory MUST
   be empty at this point (nothing copied into it yet), then:
   ```bash
   npx nuxi@latest init . --template minimal --packageManager npm --gitInit=false --no-install --force
   ```
   (`--force` is safe here only because the directory is still empty — never run this after
   copying any of this skill's own files into `gui/`, or `nuxi` will overwrite them.)

6. **Install frontend dependencies** (still inside `gui/`):
   ```bash
   npm install @mdi/font pinia sass-embedded valibot vite-plugin-vuetify vuetify vue
   npm install -D @hey-api/openapi-ts @nuxt/eslint @pinia/nuxt @unocss/nuxt \
       @unocss/preset-attributify @unocss/preset-icons @unocss/preset-wind4 unocss \
       vitest vue-tsc typescript eslint
   ```
   (`nuxt`/`vue` are already present from `nuxi init`; re-installing `vue` here is harmless.
   Some devDependencies above may already be present from the `nuxi` template — `npm install`
   no-ops on those, it doesn't duplicate or downgrade.)

7. **Layer the frontend reference files on top**, replacing the nuxi-generated file of the
   same name: `nuxt.config.ts`, `openapi-ts.config.ts`, `uno.config.ts`, `app/app.vue`, and
   `app/plugins/vuetify.ts` (new file — create the `plugins/` directory). Also:
   - Copy `references/CLAUDE.gui.md` to `gui/CLAUDE.md`.
   - Merge `references/package-scripts.json`'s `"scripts"` entries into the generated
     `package.json` (don't replace the whole file — `dev`/`build`/`generate`/`preview`/
     `postinstall` from `nuxi` stay as-is). Rename `package.json`'s `"name"` field from
     whatever `nuxi` set (the directory basename, `"gui"`) to the real `appName`.
   - `gui/eslint.config.mjs` does not exist yet at this point — `@nuxt/eslint` only
     generates it once Nuxt runs with the module registered (which the `nuxt.config.ts` you
     just copied does). Run `npx nuxt prepare` once to generate it, THEN edit it per
     `references/eslint-generated-ignore.md` (ignore `app/generated/**` — hey-api's
     generated code trips the default lint rules).
   - Append `references/gitignore.gui-additions`'s contents to the `nuxi`-generated
     `gui/.gitignore` (the committed OpenAPI snapshot needs an explicit re-include, since
     everything else under `app/generated/` should stay untracked — git needs each
     intermediate directory re-included too, not just the file itself; see the comment in
     that reference file).

8. **Fill in the root `CLAUDE.md`'s** one-line "what this is" placeholder once the app's
   actual purpose is known.

## Verification

Don't report the scaffold as done until all of these pass:

- `cd api && uv run uvicorn main:app --reload` boots without error; `curl localhost:8000/health`
  returns `{"status": "ok"}`.
- `uv run pytest` passes (`test_health`).
- `uv run ruff check . && uv run mypy .` clean.
- `cd gui && npm run dev` boots; `curl localhost:3000/` returns 200 with Vuetify's SSR classes
  present (`v-application`, `v-theme--*`) — proves Vuetify is actually wired in, not just that
  the config parses.
- `npm run typecheck` clean.
- With the backend running, `npm run openapi` succeeds and produces a (near-empty, since no
  routes exist yet) generated client under `app/generated/rest/` — this proves the codegen
  pipeline end-to-end, not just that the config file parses.

## Common mistakes

- **Scaffolding into an unconfirmed directory.** Always resolve `targetDir` with the user first.
- **Hand-writing a dependency version** into `pyproject.toml` or `package.json` instead of
  `uv add`/`npm install`. See "Package versions" above.
- **Leaving `__APP_NAME__` placeholders un-replaced** in `main.py`/`.env.example`/etc. — grep
  for the literal string after copying, don't eyeball it.
- **Running `nuxi init --force` after `gui/` already has this skill's files in it** — it will
  clobber them. Always init first, into an empty directory, then layer files on top.
- **Wiring auth into `/rest` anyway** "to be safe" — the deferred-auth decision is deliberate;
  adding it unasked means guessing an auth scheme (session? OIDC? JWT?) the user hasn't chosen yet.
- **Building out a real `ApiKey` DB model** for the `/api` surface instead of the placeholder
  header check — that's real domain modeling belonging to a later, explicit decision, not this scaffold.
- **Pointing `gui/openapi-ts.config.ts` at a live URL** instead of a committed snapshot — breaks
  reproducibility and fails against self-signed dev certs in some HTTP clients; always snapshot-then-generate.
- **Running `npm run openapi` before the backend is up** — the curl step will fail; start the
  backend first.
- **Forgetting the `app/generated/**` ESLint ignore or the `.gitignore` re-include rule** —
  `npm run lint` fails on hey-api's own generated code, and generated build output otherwise
  gets committed alongside the snapshot that's supposed to be the only tracked artifact.
